# 0005. Support English, Ukrainian and Russian with typed in-code catalogs

- **Status:** Accepted
- **Date:** 2026-10-10

## Context

The bot's friends speak English, Ukrainian and Russian. Each user must be able to choose
their language. UX is the main differentiator of this bot, so copy has to read naturally
in every language, not like a literal translation. The project should stay simple: three
languages, a few dozen strings, one developer.

## Decision

- **Languages:** `en`, `uk`, `ru`. English is the canonical source copy.
- **Choice:** on joining (invite accepted, or a config admin's first update) the bot
  stores Telegram's `language_code` (falling back to English) in `users.language` as a
  provisional language. While `users.language_chosen` is false, `/start` shows the
  language picker before the welcome; any pick stores the language and sets the flag, and
  later `/start`s show only the welcome. `/language` changes it at any time. Rows that
  existed before the flag was added see the picker on their next `/start`.
- **Mechanism:** typed Python catalogs, no i18n library.
  - One module per language under `bot/locales/` (`en.py`, `uk.py`, `ru.py`).
  - Each catalog is an instance of one frozen dataclass of strings, so mypy fails if
    a language is missing a key or has a typo.
  - Strings with values use named `str.format` placeholders.
  - A small `plural()` helper covers the one/few/many forms that Ukrainian and Russian
    need (1 трек / 2 треки / 5 треків).
- Handlers get the user's catalog through middleware and never contain literal copy.
- Bot command descriptions (`setMyCommands`) are registered for each language.

## Alternatives considered

- **gettext via `aiogram.utils.i18n` + Babel** - the standard toolchain, but it needs
  extract/compile steps and `.po` files. That's heavy for ~50 strings, and it has no
  compile-time check for missing keys.
- **Project Fluent (`fluent.runtime`)** - excellent plural and grammar support, but it
  adds a dependency and a new file format for a problem a 10-line helper solves here.
- **English only** - rejected; the friends are Ukrainian and Russian speakers.

## Consequences

- Adding a string means adding a field to the dataclass and a value in all three
  catalogs. mypy enforces it, and translations can't silently go missing.
- No runtime dependency is added.
- If the copy grows a lot (e.g. the Mini App) or outside translators join, revisit this
  with Fluent or gettext in a new ADR.
- AGENTS.md's "strings live in `bot/texts.py`" rule becomes "strings live in
  `bot/locales/`".
